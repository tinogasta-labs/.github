# Contributing to Tinogasta Labs

We’re excited to have you contribute to our projects! To ensure smooth collaboration and maintain the quality of our open-source projects, we have a few guidelines we ask contributors to follow.

## 1. Open an Issue Before Starting a PR

Before submitting a pull request (PR), please open an issue to discuss the changes you want to make. This helps us ensure that the proposed changes align with the project's goals and that they don’t overlap with ongoing work. Additionally, we believe everyone's time is valuable, and we don’t want you to work on something that’s already being handled or that won’t be used.

[Creating an issue](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-an-issue)

## 2. Creating a PR

When you're ready to submit your changes, ensure your pull request follows these steps:

- Fork the repository if you haven’t already.
- Clone your fork and create a new branch for your changes.
- Make your changes and write clear, concise commit messages.
- Ensure your changes pass all tests, follow coding standards, and don’t break existing functionality.
- Link your pull request to the issue: In the pull request description, reference the issue it addresses (e.g., `Closes #123`).

[Creating a pull request](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/creating-a-pull-request)

## 3. Code of Conduct

We value respectful, inclusive, and productive collaboration. By contributing to our projects, you agree to abide by our [Code of Conduct](CODE_OF_CONDUCT.md).

Thank you for your contributions! We look forward to working with you to improve our projects.
